# 手机与平板布局适配

600px 以下保留手机 rpx 布局；600px 起进入平板样式。正文最大宽度为 720px，字号、头像、触控区和导航栏使用 px 上限，避免随屏幕宽度继续放大。登录背景仍全屏覆盖，登录内容单独限宽。

普通平板字号为正文 20px、标题 28px；大字模式为正文 24px、标题 32px。底部导航普通模式 64px、大字模式 72px，安全区额外计入。底部固定操作栏与正文使用同一最大宽度。

服务和订单页的 swiper 填满剩余高度，不再强制至少 400rpx。列表外壳保持屏幕宽度，内部卡片限宽，以便原有滑动距离计算继续匹配真实 swiper。窗口变化通过 onResize 更新宽度并清除旧手势状态。app.json 开启 resizable，参考[微信官方示例配置](https://github.com/wechat-miniprogram/miniprogram-demo/blob/master/miniprogram/app.json)。

## 验证

- `node --test miniprogram/tests/*.test.cjs`：145 项通过，包括横竖屏后滑动距离回归。
- 微信开发者工具自带 wcsc：19 个 WXSS 文件编译通过。
- `node miniprogram/scripts/verify-responsive.cjs`：使用实际项目 WXSS 和简化 DOM 场景检查首页、个人中心、服务列表、订单列表和底部导航；覆盖 320×568、375×667、768×1024、1024×768、1366×768，以及普通/大字模式。
- 运行 CSS 场景脚本需要 Playwright，可通过 NODE_PATH 指定已有安装；本机使用 `PLAYWRIGHT_CHANNEL=msedge`。截图可通过 `RESPONSIVE_SCREENSHOT_DIR` 指定输出位置。

这些是浏览器 CSS 排版检查，不是微信真机验收。仍需在平板微信中复核原生 swiper/scroll-view、实际安全区、系统字体、头像与地图等原生组件，并测试分屏宽度经过 600px 临界值。无需切换身份或改动业务数据即可检查排版。

## 首页真机截图后的补充调整

截图显示进行中订单的身份标签仍使用 26rpx，部分图标和纵向间距也没有封顶。已将平板身份标签改为普通 15px／大字 18px，订单图标改为 22px，并收紧标题、元信息及按钮间距。

宽度达到 900px 时，首页最大宽度扩展至 1120px：当前服务与四个快捷入口分为左右两栏，推荐服务使用双列。600–899px 保持单列并使用紧凑间距；手机继续沿用原有排列。加载占位和订单实内容使用相同分栏结构。

布局脚本补入从实际首页 WXML 提取的老人自约、家属代约场景，检查标签字号、订单卡片高度、进度按钮首屏可见性及宽屏双列布局，共 70 组场景通过。145 项逻辑回归通过，首页 WXML 和 WXSS 编译通过。
