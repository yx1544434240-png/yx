## 整改结果

| 编号 | 结果与实现 |
| --- | --- |
| H1 | 默认 prod，dev-mode 默认 false；模拟登录只有显式 dev/test、非 prod 且 APP_DEV_MODE=true 时注册并放行。prod 禁用 Swagger。 |
| H2 / N3 | 头像回退使用相对路径，服务封面使用公开 service-images 路径；请求 Host 不参与地址拼接。可配置 APP_PUBLIC_BASE_URL，须包含 /api。小程序按当前 API 地址显示、下载图片。 |
| H3 / N1 / N7 | 删除测试字节放行分支；校验完整 PNG 签名、JPEG/WebP 签名及后缀匹配；测试使用真实图片。通用图片单文件 5MB、请求 10MB，服务封面 2MB。上传按角色、用途控制，每用户每分钟20次；Nginx补充入口限流。 |
| H4 / N2 | URI 精确校验协议、主机、端口和路径；拒绝域名包含绕过、userinfo、查询串、编码路径和穿越。新头像路径绑定上传人；履约照片绑定订单、上传人及实际文件。 |
| N4 / M4 | 过期订单转 WAIT_MANUAL 后正常提交；重复触发不重复记日志，不生成派单或预留。已增加真实 MySQL 落库回归。 |
| N5 / M1 | CORS 默认加入后台3000端口，生产通过 APP_CORS_ALLOWED_ORIGINS 配置。禁止携带跨域凭据。 |
| N6 | 新履约照片仅存于独立私有目录；下载接口验证登录、订单关系及是否已提交，响应 no-store。小程序携带 Authorization 下载到临时文件，退出/失效时清理；后台鉴权下载后用临时 blob 预览。不存在公开的履约图片静态映射。 |
| 历史图片 | 启动迁移：读取受信任的旧本地/COS照片，复制到私有目录，事务更新履约记录与清理任务，再清除公开源文件。失败任务持久保留并阻止启动完成，重启重试。COS任务记录原桶，避免更换配置后误删其他桶。初始化及迁移完成前返回503。 |
| M7 | 集成测试使用 Testcontainers，按摘要锁定 MySQL 8.4.11；不再依赖 MariaDB 的 innodb_snapshot_isolation。测试媒体使用专用临时目录。不接受外部数据库地址作为测试库。 |
| M8 | 扫描任务使用同一数据库连接获取/释放 MySQL 会话锁，跨实例互斥；每轮最多扫描200条，进程断开后锁由数据库释放。已验证竞争及异常释放。 |
| M9 | 增加前后端 Dockerfile、Compose、Nginx代理、独立数据卷和 GitHub Actions；SQL日志改走SLF4J。生产Compose仅导入表结构，演示数据通过 compose.demo.yml 显式添加。 |
| M10 | 订单、老人、服务项目、履约记录使用受限DTO/输入校验；补充评价、投诉、排班、审核、分页校验。禁止客户端控制履约人员、实际签到时间、评价人、投诉处理状态等字段；限制分页数量。 |
| P8 | 保留管理员核验代确认，必须手写10至220字依据，不再预填结论；订单时间线记录操作人、角色及原因，并写管理审计日志。 |
| P10 | 订单下单人是费用协调责任人，VO明确payerUserId/payerName；预约及详情显示线下结算说明。金额为预约价格快照，系统不发起扣款或虚构支付状态。 |
| P12 | 订单详情、轨迹、取消、评价、投诉共用 OrderAccessPolicy，未知角色默认拒绝；静态资源不再因非HandlerMethod而直接放行；令牌权限以数据库当前角色复核。 |
| L1 / L6 | 上传测试移除真实桶名；删除未引用的vite.svg和hero.png。私有配置及.env均忽略提交，Docker上下文排除密钥文件。 |
| L3 | operation_log用于管理员写操作和历史图片清理任务。管理写操作与审计同事务，审计失败会回滚业务变更；新增管理员日志查询接口及后台页面。日志不记录密码、令牌或完整请求体。 |
| 默认凭据 | dev也不再提供数据库账号/口令默认值。空库首次启动需显式提供管理员密码，经BCrypt存储；已有管理员时不覆盖密码。 |

上一轮已完成的手机号保护、通知归属、排班归属、WAIT_CONFIRM禁改派、JWT敏感字段移除、首页骨架屏和适老字号等保留，并纳入回归。

文件签名检查不等同于完整图像解码或照片内容真实性鉴定；历史图片按原履约记录关联迁移，不自动判断照片拍摄内容。

## 已执行验证

- 后端 mvn verify：78项通过，含真实MySQL业务流、并发接单、过期订单落库、写入后回滚、调度锁、管理审计原子性和私有照片上传/读取/提交闭环。
- 写入后回滚用例先在事务内确认评分、派单尝试、排班预留均存在，再注入失败并验证三者全部回滚，避免“还没写入就失败”的假验证。

- 后台6项测试及生产构建通过；仍有既有的大块资源提示，不影响构建或权限验证。
- 前后端Docker镜像均实际构建成功；Compose配置校验通过。随机项目的临时容器中，空库初始化、管理员真实登录、禁用模拟登录、服务新增、审计记录、私有照片匿名拒绝及后台HTTP页面全部验收通过，测试容器及数据卷已清理。
- 历史迁移单测验证复制、提交、删除顺序，重复运行和清理失败保留任务。未接触真实COS桶执行删除。
- 硬件耗时不再作为跨机器CI的固定亚毫秒承诺；算法功能与对比断言仍执行。独立性能验收可显式设置 -Dbenchmark.max-latency-ms=1。

手机扫码、真实微信授权和真实COS资源的验收需要对应设备/资源环境，不能由以上测试冒充。CI工作流已配置，本地运行了对应验证；尚未向远程仓库推送触发Actions。

## 运行方式变化

详见 [部署与测试](14-部署与隔离验收.md)。本地开发显式设置SPRING_PROFILES_ACTIVE=dev、DB_USER、DB_PASSWORD和JWT_SECRET；空库还需BOOTSTRAP_ADMIN_PASSWORD。后端重启、小程序重新编译后才能使用新增接口。

历史COS照片迁移需要原桶的读/删权限与原桶配置；迁移或清理失败会保留任务并停止完成启动，禁止通过关闭迁移绕过私密照片整改。不要直接把已有业务数据库的表结构脚本重新导入；本轮没有新增业务表，复用已有operation_log。
