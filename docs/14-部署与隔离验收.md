# 部署与隔离验收

## 本地开发

在IDEA运行配置中设置：

- SPRING_PROFILES_ACTIVE=dev
- DB_USER、DB_PASSWORD：本机数据库账号和密码，已无内置默认口令。
- JWT_SECRET：至少32字节的随机密钥；更换后旧登录会失效。
- BOOTSTRAP_ADMIN_PASSWORD：仅空库首次启动需要，12至72字节；已有管理员不重置其密码。

微信和COS本地配置文件仍仅在dev加载，文件已忽略Git提交。只有答辩需要免密切换时，额外设置APP_DEV_MODE=true；正常微信登录无需开启。

小程序新增私有照片使用wx.downloadFile携带Authorization下载；正式微信环境需为后端HTTPS入口配置request、uploadFile、downloadFile合法域名。开发真机联调仍需手机能访问当前局域网API地址。

## Docker运行

1. 复制.env.example到.env，填写随机的MYSQL_ROOT_PASSWORD、DB_PASSWORD、JWT_SECRET及首次启动管理员密码。不要提交.env。
2. 设置微信配置；默认图片走本机持久化目录。需要固定图片完整地址时配置APP_PUBLIC_BASE_URL，例如https://care.example.com/api。
3. 执行docker compose up -d --build。
4. 后台默认http://localhost:3001，API默认http://localhost:8081/api。端口仅绑定127.0.0.1，正式发布通过自有HTTPS入口代理；CORS填写实际后台来源。

数据库和上传文件分别存于命名数据卷；初始化脚本只在新数据库卷上执行。生产Compose不会导入演示账号。空库管理员由显式密码初始化，密码不会写入日志。

本地演示需要导入样例角色和订单时，在新演示卷上使用：

```text
docker compose -f compose.yml -f compose.demo.yml up -d --build
```

该命令的演示数据不能作为生产账号使用。不要对已有业务数据卷运行down -v；这会删除其持久数据。

数据库镜像按digest锁定为MySQL8.4.11；后端业务时区为Asia/Shanghai，数据库默认+08:00。多主机部署时，所有API实例须使用共享私有图片存储目录及同一数据库；本地命名卷仅适用于同一Docker主机。

## 测试与CI

需要运行中的Docker引擎。Windows可使用：

```powershell
./scripts/verify-backend.ps1
```

如mvn不在PATH，可传入-Maven指定mvn.cmd的绝对路径。脚本仅调整本次子进程PATH，避免个别Windows JDK错误解析中文路径。Linux/macOS直接运行mvn -B -f backend/pom.xml verify。

后端集成测试默认创建临时MySQL容器、导入样例数据，使用临时媒体目录；测试结束由Testcontainers回收容器。测试不连接本机业务3306，也不修改原有上传目录。

其他检查：

```text
cd admin-web
npm ci
npm test
npm run build
```

```text
node --test miniprogram/tests/*.test.cjs
```

前后端镜像构建完成后，可用Python运行scripts/verify-compose.py：在随机项目名的临时数据卷中，验证空库初始化、登录、禁用模拟登录、服务新增、审计记录、私有照片匿名拒绝及后台HTTP页面，结束自动清理自己的容器与数据卷。此脚本使用8081/3001端口，这两个端口需空闲。

.github/workflows/verify.yml在push或PR上运行后端、前端、小程序测试及Docker构建。尚未推送时，不应把“工作流文件存在”表述为“远端Actions已成功”。

## 图片迁移与审计

应用启动时先初始化管理员并迁移旧履约照片。旧本地目录按原app.upload-fallback-dir读取；旧COS需要原桶、域名及凭据配置。复制与数据库更新成功后，才执行公开副本清理；待清理任务保存在operation_log中，重启可重试。

私有目录app.private-media-dir必须与公开图片目录分离。新履约上传须传orderId，只有当前接单且服务中的人员可上传；提交记录时核对该订单及上传人。后台管理操作写入operation_log，可在“操作日志”页面查看；审计写入失败会回滚同次业务操作。
