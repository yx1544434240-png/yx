# 工作人员资质证明提交与审核

## 使用入口

- 小程序使用工作人员账号登录，在「我的 → 我的资质证明」提交材料、查看状态或补充被退回的申请。
- 管理后台进入「服务人员 → 待审核资质」，查看证书图片、编号并通过或退回；也可以在具体人员的「资质与班次」中查看每条资质。
- 每个工作人员的每种技能只保留一条资质记录。通过后才计入小程序专业技能展示及派单技能匹配。

## 提交与审核规则

1. 工作人员填写技能分类、资质名称、证书编号，上传 1–3 张 JPG/PNG/WEBP 图片，每张不超过 5MB。
2. 后端从登录身份确定申请人，验证图片实际内容、上传归属及文件是否存在。提交后状态为 PENDING（待审核）。
3. 管理员查看材料后可通过（APPROVED），或填写不超过 200 字的原因后退回（REJECTED）。记录审核人及审核时间。
4. 工作人员可以修改退回申请的名称、编号及图片，重新提交后再次进入待审核。技能分类不能在补充时更换。
5. 待审核或已通过的申请不能直接修改。提交版本 revision 防止管理员用旧材料页面覆盖新申请，条件更新防止重复审核。
6. 历史管理员直接录入的资质继续保留原状态，显示来源；没有图片的历史记录不会伪装成已经上传材料。

## 私有图片与权限

证明材料保存在 `app.private-media-dir` 下的 `credentials/<userId>/`，通过受鉴权保护的 `/media/private/credentials/<userId>/<filename>` 读取。仅工作人员本人和管理员可查看；管理员只能查看已关联到提交记录的图片。居民和其他工作人员不能读取证明材料。

小程序先鉴权下载到临时文件再预览；后台使用鉴权请求取得 Blob。响应包含 `Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。返回给居民的人员信息仅含已通过技能的名称和分类，不包含证书编号、审核意见或证明地址。

本功能使用本地私有文件存储，不依赖公开 COS 链接。数据库与私有目录应一起备份。移除表单图片不会立即物理删除文件；未提交的图片不会提供给管理员，清理孤立文件可另按保存期限实现。

## API（相对于 /api）

| 方法和路径 | 角色 | 用途 |
| --- | --- | --- |
| POST /staff/credentials/upload | STAFF | multipart 字段 file，返回私有相对地址 |
| POST /staff/credentials/submit | STAFF | 提交或补充；包含 skillCode、skillName、certificateNo、proofUrls；补充带 id、revision |
| GET /staff/my-profile | STAFF | 本人全部资质及审核信息 |
| GET /staff/credentials/page | ADMIN | pageNum/pageSize/status 查询已提交申请 |
| GET /staff/credentials/{id} | 本人 STAFF / ADMIN | 单条申请与材料信息 |
| POST /staff/credentials/audit | ADMIN | id、revision、approve、reason |
| GET /media/private/credentials/{ownerId}/{filename} | 本人 STAFF / ADMIN | 鉴权读取证明图片 |
