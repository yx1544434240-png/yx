# 服务实景图片与后台维护

## 已实现

- 小程序首页四类入口：助餐送餐、居家保洁、代买代办、陪同办事，使用实景照片。
- 首页服务推荐、服务列表、服务详情使用服务项目的展示图。
- 默认图已下载并压缩到项目中，按分类回退，不依赖 Pexels 在线加载。
- 后台“服务项目”列表显示缩略图；编辑项目可上传替换、预览或恢复分类默认图。
- 每类首页入口采用该分类中排序最靠前的上架服务项目图片；项目列表和详情使用各自的图片。

## 使用步骤

1. **重新启动后端**，加载新增图片上传接口和静态图片资源映射；不需要执行数据库迁移。
2. 管理后台 → 服务项目 → 编辑 → 上传替换图片。
3. 点击“保存项目”才更新服务展示图。取消编辑不会更改原项目图片。
4. 小程序重新编译；后续换图后，在首页下拉刷新。列表目录缓存最长60秒，后台保存并不会主动推送到已经打开的手机页面。

图片必须是 JPG 或 PNG、单文件不超过2MB；上传接口还检查真实文件内容与像素数量，并统一编码为最大边1600像素的 JPEG，不接受 SVG。匿名和普通居民不能上传。上传失败或尚未完成时不能保存项目。

## 存储与部署

- 使用现有 `service_item.icon` 字段保存图片相对路径，不增加数据库字段。
- 上传接口：管理员 `POST /api/service-items/image`，multipart 字段 `file`。
- 上传后返回 `/media/service-images/{UUID}.jpg`，保存到服务项目后，小程序使用当前后端地址解析图片。
- 图片读取：`GET /api/media/service-images/{filename}`，展示图允许公开读取。
- 文件默认存放在后端工作目录下 `uploads/service-images/`，已加入 Git 忽略。
- 可以通过 `app.service-images-dir` 配置持久目录。正式部署建议使用固定绝对路径，并备份该目录；不要放入密钥、文档或其他私人文件。
- 上传文件名由服务器生成，不使用原始上传路径。每次换图返回新 URL，避免浏览器或手机沿用旧图缓存。
- 上传但未保存的图片暂留存储目录；后续运维可按数据库引用关系清理长期未使用文件，不应直接删除仍被项目引用的照片。

默认图片出处和摄影者记录见 `miniprogram/assets/photos/services/README.md`。管理后台和后端内的默认图与小程序一致。

## 验证范围

新增前端回归覆盖默认分类图、旧图标名兼容、真机服务地址解析、图片失败回退、第四分类入口，以及后台保存后目录强制刷新。

新增后端隔离测试覆盖真实图片上传与尺寸优化、伪造 JPG/SVG 拒绝、空文件和超限文件拒绝、匿名和普通居民上传拒绝、管理员上传成功，以及默认照片和上传照片可被公开读取为 JPEG；测试文件只写入 JUnit 临时目录，不连接或修改当前业务数据库。
