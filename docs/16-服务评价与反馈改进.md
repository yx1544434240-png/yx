# 服务评价与反馈改进

## 居民操作

服务完成后，从订单详情进入评价。页面根据有权限访问的订单详情接口读取服务名称、人员和完成时间，不采用 URL 中的展示文字作为评价依据。

评分初始为未选择。选择分数后可以多选快捷标签，补充文字选填，前后端均限制为 200 字。一至二星可选择“需要社区协助处理”，初始关闭；主动开启且选择主要问题后，才会随评价创建反馈记录。高分评价不会自动创建投诉，改为高分时清除低分问题和跟进选择。

草稿按服务器、账号 ID、订单分别保存，有效期七天。输入采用延迟写入，离开页面时保存；网络失败保留内容；成功提交后删除草稿并显示结果页。会话变化后旧请求不会覆盖新账号页面。每单只允许一条评价，仍使用原数据库唯一约束。

订单详情展示评价标签以及当前居民自己提交的反馈状态、答复、答复时间。家属即使有订单查看权限，也不会获得其他账号的反馈记录。服务人员不会获得投诉处理记录。管理员可查询关联反馈。

## 社区后台

反馈处理支持按状态筛选和分页。管理员可先受理（PENDING → PROCESSING），再填写处理答复并办结（→ RESOLVED）；也保留直接处理待受理记录的能力。状态更新包含条件，重复受理和重复办结会被拒绝。界面不再声称已发送尚未实现的外部通知。

新增 `POST /fulfillment/complaint/start`，只允许管理员操作。评价接口使用独立 ReviewSubmitDTO，增加 followUp 和 issueType 字段。评价与用户主动申请的反馈记录在同一 Spring 事务中写入。后台受理、办结沿用管理员操作审计。

## 界面

手机纵向排列；宽屏平板将服务摘要和评价表单分列。标签支持换行，按钮保留按压反馈，评分星星和控件在平板上限制尺寸。提交后不立即跳走，可主动查看订单或反馈记录。

## 验证

按用户要求，不使用 Docker 或业务数据库进行验收。

- 后端 85 项无数据库单元测试通过，包括评价同意条件、标签与字数校验、重复提交和反馈状态冲突。
- 小程序 177 项测试通过，包括主动评分、草稿隔离、失败重试、防连点、会话切换。
- 后台 7 项测试及生产构建通过。
- 80 组 CSS 排版检查通过；评价、订单详情、反馈页面 WXML/WXSS 编译通过。

后端命令：`mvn -f backend/pom.xml test -Dtest=*Test,!*IntegrationTest,!DispatchConcurrencyAndTransactionTest`。JDK 23+ 需补 `-Dmaven.compiler.proc=full`。

没有执行数据库集成测试或微信真机端到端测试，事务回滚和真实数据库权限联动仍需本地联调确认。本次无数据库结构变更，无需迁移脚本；使用新接口前需重启后端并重新编译小程序。
