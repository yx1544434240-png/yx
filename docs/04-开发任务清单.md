# 开发任务清单

所有任务当前均未完成。以下按依赖顺序推进，参考周期为十二周，可按学校日期调整。

## M0：需求与设计基线（第 1～2 周）

- [ ] 核对学校任务书、论文模板、答辩与提交日期。
- [ ] 核验微信开发账号、演示方式和正式运行的接入条件。
- [ ] 确定四类服务的说明、价格、预计时长与技能要求。
- [ ] 绘制居民、服务人员、管理员核心页面原型。
- [ ] 复核角色权限、家属授权、订单状态与异常规则。
- [ ] 将数据库草案落实为 ER 图、数据字典及迁移脚本设计。
- [ ] 整理开题材料与相关文献，明确实验研究问题。

完成标准：页面、状态、字段与规则能够互相对应，首版范围明确；尚不据此宣称功能已实现。

## M1：基础工程（第 3 周）

- [x] 初始化后端、小程序和管理后台目录。
- [x] 选择并锁定依赖版本，加入构建锁定文件与版本说明。
- [x] 完成数据库连接、迁移与演示数据加载。
- [x] 完成统一接口响应、参数校验和异常返回。
- [x] 完成登录、身份识别、后端权限拦截。
- [x] 区分开发与演示配置，密钥通过环境配置提供。
- [x] 建立业务测试和数据库集成测试的运行入口。

完成标准：按说明可启动，能够登录；未登录或无权限请求被拒绝；数据库迁移可重复部署。

## M2：基础资料与人工派单闭环（第 4～6 周）

- [x] 完成老人档案、家属绑定与管理员审核。
- [x] 完成服务项目、人员资料、技能和班次。
- [x] 完成预约下单、幂等提交、列表与详情。
- [x] 完成人工派单及时间预留。
- [x] 完成接单、拒单、开始服务与服务记录。
- [x] 完成服务确认、管理员有据代确认及评价。
- [x] 完成服务开始前取消及预留释放。
- [x] 验证核心权限、状态转换和不可行排班。

完成标准：AC-01、AC-02 及相关权限场景可实际演示；一笔订单从创建完成到评价，历史状态可追溯。

- [x] 实现四项评分、冷启动、稳定排序与参数版本。
- [x] 保存候选评分、排除原因和选中依据。
- [x] 实现顺序派单、接单期限与尝试次数上限。
- [x] 实现拒单重派、超时重派、待人工处理。
- [x] 完成人工撤销分配、改派和新轮次调度。
- [x] 实现重启后任务恢复与幂等通知。
- [x] 验证同一人员竞争、超时与接单竞争、取消竞争。

完成标准：AC-03～AC-15 中与派单有关的场景有实际结果；不存在重复有效分配和冲突预留。

## M4：页面与管理完善（第 9 周）

- [x] 调整老人端字号、点击区域、预约确认与进度展示。
- [x] 完善人员今日安排、后台待处理队列与派单解释。
- [x] 完成投诉处理、站内通知和关键操作日志。
- [x] 完成统计图表，并统一状态和时间口径。

完成标准：核心角色能够独立完成其任务，异常有明确反馈，页面数据与后台业务事实一致。

## M5：测试与实验（第 10 周）

- [ ] 为高风险规则编写并执行有意义的单元及集成测试。
- [ ] 按验收表逐项记录输入、操作、预期、实际结果和证据。
- [ ] 完成轮询、距离优先与综合评分三种策略。
- [ ] 生成可复现的多规模、多约束实验数据。
- [ ] 分别运行策略，保存原始结果及环境参数。
- [ ] 比较成功率、准时率、路程、负载、重派与耗时。
- [ ] 开展权重敏感性分析，保留独立验证场景。
- [ ] 根据实际结果形成图表、结论和局限分析。

完成标准：测试结论能由记录支持，实验能由保存的输入和配置复现；无虚构提升比例。

## M6：论文、部署与答辩（第 11～12 周）

- [ ] 完成论文，检查文中状态、表结构与最终代码一致。
- [ ] 整理部署、数据初始化、账号及使用说明。
- [ ] 在目标环境完成一次从空库开始的部署验证。
- [ ] 准备正常履约、拒单或超时重派、排班冲突三个演示场景。
- [ ] 准备答辩 PPT、演示脚本、录屏与数据库备份。
- [ ] 检查项目不包含有效密钥和真实个人资料。
- [ ] 整理源代码、论文、测试与实验产物清单。

完成标准：应用可部署、关键流程可演示、材料与系统一致，演示故障时有可用备份。

## 执行记录模板

每次完成一个模块，记录以下内容：

```text
模块：
实现范围：
对应需求与验收编号：
实际验证方式和结果：
已知限制：
需求或数据库变更：
下一项依赖任务：
```

文档写作同步推进：需求完成后整理需求分析；数据库落地后更新 ER 图与数据字典；实验执行时同步保存输入、结果和图表。
