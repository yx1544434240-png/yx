# 小程序流畅度优化说明

本次针对滚动和点击掉帧的代码风险做局部优化，保留原有页面风格和原生左右滑动。

## 保留的平滑反馈

- 服务页与订单页继续使用原生 swiper，过渡时间为 220ms。
- 分类滑块使用固定宽度，按百分比做 transform 位移，时长 200ms。文字大小保持稳定，不在切换时改变字号。
- 卡片按下立即反馈，按钮保留短时透明度过渡。工作台请求期间显示 loading 并锁定重复提交。
- 大字版仍使用字号与控件变量；CSS 提供 reduced-motion 降级。

## 减少的渲染工作

1. 滑动完成后，仅挂载当前分类及相邻分类的滚动内容，最多 3 个列表。过渡期间保留离开和进入的页面，避免提前销毁造成闪白；快速连续切换时可临时保留更多页面，最后一次动画完成后再释放。
2. 分类位置由固定宽度布局决定，移除每次点击的布局查询、80/100ms 定时测量及手工列表高度计算；页面剩余高度由 flex 布局分配。
3. 原始服务与订单缓存留在逻辑层，视图只接收卡片需要的字段；订单记录中的日志、履约详情等不进入列表 data。
4. 订单分页通过数组路径追加新增行，已有行不重复传输；切换动画期间暂缓响应结果的列表更新，动画结束后补齐。
5. 派单倒计时拆成独立组件，每秒只更新倒计时文字；进入后台停止计时，返回后按实际截止时间重新计算，避免漂移。
6. 工作台原始任务保留在实例缓存，仅筛选后的列表进入 data；输入服务总结时先保存逻辑层值，提交时读取，减少逐字输入引起的页面更新。

## 数据刷新规则

- 服务目录共享 60 秒内存缓存，首页与服务页合并重复请求。有效的空列表也会缓存；切换后端地址时隔离旧结果。
- 订单与工作台在返回页面时使用 15 秒新鲜期；下拉刷新可强制更新。预约、取消、确认、评价、接单和履约操作会使订单缓存失效。
- 账号或后端地址变化后清理订单视图缓存，忽略此前未完成请求的结果；请求途中发生订单变更时补发一次新读取。
- 个人中心按订单状态跳转改用 switchTab，通过一次性筛选状态传递分类，修复 navigateTo 不能打开 TabBar 页的问题。

## 页面跳转优化（2026-10-20）

- 新增统一的 navigation 工具，同一时刻只发起一次原生路由调用。重复点击不会叠加详情页；失败后解锁，登录守卫等待当前跳转结束后执行，不使用固定定时器。
- 去掉登录/退出后的 400ms、登录失效后的 500ms、预约/评价/档案保存后的 1000ms 等待。成功提示与跳转同时触发；提交期间保持防重锁，预约跳转失败后只重试打开已创建的订单。
- 登录成功后按目标页使用 switchTab 或 redirectTo。受保护的非 TabBar 页面使用 redirectTo 打开登录，避免返回时再次跳登录；修复评价页回跳参数 orderId。常规流程不再使用 reLaunch。
- 合并同一登录态的多个 401 响应，只清理一次状态、打开一次登录。旧账号或旧后端的延迟响应不会清除新会话；账号密码错误留在登录表单。
- 服务目录、服务详情与预约页共用 60 秒缓存和在途请求。缓存命中时详情页 onLoad 即显示服务信息，减少“列表→详情→预约”的重复网络等待；更换后端后隔离缓存与旧响应。
- 订单详情使用 15 秒新鲜期，返回页面时合并重复请求。订单变更、下拉刷新与重试会重新读取，不能用缓存吞掉状态更新。
- 返回服务/订单/个人中心时减少不变状态的 setData；中断分类滑动再返回时仍会释放远处列表。详情页首次读取增加静态骨架占位、错误提示和重试入口。
- 将 requiredComponents 按需注入配置放到 app.json 中，移除嵌套 project.config.json 中无效位置的同名设置。配置位置参照[微信官方示例](https://github.com/wechat-miniprogram/miniprogram-demo/blob/master/miniprogram/app.json)。保留 180ms 底部指示条与 220ms 原生 swiper 过渡。

## 验证

运行命令（项目根目录）：

```powershell
node --test miniprogram/tests/ui-flow.test.cjs miniprogram/tests/performance-flow.test.cjs miniprogram/tests/tab-bar.test.cjs miniprogram/tests/navigation-flow.test.cjs
```

40 项自动化逻辑测试通过，覆盖缓存共享与过期、切换后端、原生滑动的挂载窗口、连续十页增量更新、请求合并、分页失败、变更刷新、账号隔离、快速切换、分类跳转、倒计时生命周期、操作防重、连续点击防重复跳转、并发 401、登录回跳、提交后立即跳转以及路由失败重试。

使用本机微信开发者工具附带的 wcc/wcsc 编译器，14 个 WXML 模板和 15 个 WXSS 文件通过编译。另检查 20 个 JS 文件的语法与 17 个 JSON 文件。

开发者工具重新编译后检查了首页→服务列表→服务详情，页面内容均正常显示，调试器运行错误为 0。服务列表接口在本机的三次只读请求约为 117ms、9ms、6ms，仅代表该次本机测试，不能推断其他接口或真机网络耗时。

上述验证证明代码与模板的正确性，不代表真机帧率已经实测改善。建议在同一台手机和相同数据量下，对比服务页滚动、订单连续切换、翻页以及工作台倒计时运行中的操作；重点观察帧率、渲染耗时和 setData 数据量。特别复核大字版和 TabBar 上方列表的可用高度。
